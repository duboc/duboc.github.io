<section lang="en" markdown="1">

Eighty columns. Nobody asked the agent.

Most of what we call good code is ergonomics for humans. Short functions so a person can hold them in their head. Meaningful names so a stranger can guess intent. Line breaks, consistent indentation, the sacred width of a 1970s terminal. Every rule assumes the same reader: a tired human, reading slowly, with limited working memory.

Change the reader and the rules wobble. When most code is written, read and modified by models, which of those properties still pay rent? There is no proof yet that good code, as we defined it, matters at all. Some properties will survive because they help any reader, human or not: clear boundaries, honest contracts, behavior you can observe. Many will turn out to be taste dressed up as law.

Performance gets the same audit. A better algorithm or a smarter data structure can matter enormously for the top of the top one percent of software. For the other ninety-nine, there are no users waiting, no hot path, nobody executing that code often enough to care. Comparing everyday software to the elite edge case was always a mistake. When performance truly matters, the model can fix it.

None of this means craft is dead. It means craft was aimed at the wrong reader.

Write for whoever reads it next.

</section>

<section lang="pt-BR" markdown="1">

Oitenta colunas. Ninguém perguntou ao agente.

Quase tudo que chamamos de código bom é ergonomia para humanos. Funções curtas para que uma pessoa consiga segurá-las na cabeça. Nomes significativos para que um estranho adivinhe a intenção. Quebras de linha, indentação consistente, a largura sagrada de um terminal dos anos 1970. Toda regra assume o mesmo leitor: um humano cansado, lendo devagar, com memória de trabalho limitada.

Troque o leitor e as regras balançam. Quando a maior parte do código é escrita, lida e alterada por modelos, quais dessas propriedades ainda pagam aluguel? Não existe prova de que código bom, do jeito que definimos, ainda importe. Algumas propriedades vão sobreviver porque ajudam qualquer leitor, humano ou não: fronteiras claras, contratos honestos, comportamento observável. Muitas vão se revelar gosto pessoal fantasiado de lei.

A performance passa pela mesma auditoria. Um algoritmo melhor ou uma estrutura de dados mais esperta pode importar enormemente no topo do topo, o um por cento do software. Nos outros noventa e nove, não há usuário esperando, não há caminho crítico, ninguém executa aquele código o suficiente para se importar. Comparar o software do dia a dia com a exceção de elite sempre foi um erro. Quando a performance realmente importa, o modelo conserta.

Nada disso significa que o ofício morreu. Significa que ele mirava o leitor errado.

Escreva para quem vai ler depois.

</section>
